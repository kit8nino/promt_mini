Промпт-инжиниринг — это не про «магические фразы», а про дисциплину точной постановки задачи, близкую к написанию технического задания или API-контракта. Для опытного разработчика здесь нет ничего принципиально нового: вы уже умеете декомпозировать задачи, задавать границы и описывать ожидаемый результат. Именно эти навыки и составляют основу работы с LLM.

## Основная концепция: Контекст → Задача → Формат вывода

Любой промпт для production-задачи раскладывается на три ключевых блока, которые можно версионировать, тестировать и переиспользовать.

### 1. Контекст (Context / Persona)

Контекст задаёт «рамки мышления» модели: кем она должна быть, в какой предметной области работает, какие ограничения соблюдает. Это аналог system prompt в API — он определяет общее поведение, а не конкретную задачу.

Без контекста модель выбирает наиболее вероятный, усреднённый ответ. С контекстом вы сужаете пространство решений до нужного домена. Например:

**Плохо:** «Проверь этот код.»
**Хорошо:** «Ты — senior TypeScript-разработчик. Проверь код на: 1) ошибки типизации, 2) проблемы производительности, 3) уязвимости безопасности.»

### 2. Задача (Task / Instruction)

Задача — это одно конкретное действие, которое должна выполнить модель. Опытные разработчики часто недооценивают этот блок, склеивая несколько задач в один запрос. На практике лучше разбивать сложные запросы на цепочку вызовов (prompt chaining), передавая результат предыдущего шага в следующий.

Задача должна быть сформулирована глаголом: «сгенерируй», «проанализируй», «отрефактори», «сравни». Если задача допускает несколько интерпретаций — модель выберет ту, которая чаще встречалась в обучающих данных, а не ту, которую вы имели в виду.

### 3. Формат вывода (Output Format)

Формат — это контракт. Если вы интегрируете LLM в приложение, вывод должен быть парсируемым. Указывайте формат явно: JSON-схему, Markdown-таблицу, CSV, нумерованный список.

**Пример жёсткого формата:**
```json
{
  "sentiment": "positive" | "negative" | "neutral",
  "score": 1-10,
  "summary": "string"
}
```
Без явного указания формата модель может вернуть текст с пояснениями, мета-комментариями или «вот ваш JSON:» — всё это сломает парсер.

**Мини-шаблон для запоминания:**
> Ты — [роль]. Контекст: [ситуация и вводные]. Задача: [одно действие]. Формат: [структура ответа].

## Few-Shot Prompting

Few‑Shot Prompting — техника, при которой в промпт включаются несколько примеров желаемого ввода‑вывода, чтобы показать модели паттерн решения задачи. Чем более репрезентативны примеры, тем лучше модель обобщает их на новые случаи.

**Как оформить примеры**
- Каждый пример состоит из входных данных и ожидаемого результата, разделенных четкой меткой (например, `Input:` и `Output:`).
- Сохраняйте одинаковый форметку во всех примерах, чтобы модель могла выявить правило.
- Ограничьте количество примеров 2‑5; слишком много может перегрузить контекст, слишком мало — не дать достаточно сигнала.

**Когда применять**
- Задачи с неформализованным выходом (классификация, генерация форматированного текста, перевод).
- Когда нужен контроль над стилем или тонностью ответа без длительного описания правил.
- Для обучения модели новым форматам или схемам данных без дообучения.

**Пример промпта с few‑shot**

```
Ты — помощник по анализу настроений.
Input: Я сегодня чувствую себя отлично!
Output: {"sentiment":"positive","score":9,"summary":"Выражает радость и удовлетворение."}
Input: Сервис работает медленно и часто падает.
Output: {"sentiment":"negative","score":2,"summary":"Жалобы на производительность и надежность."}
Input: Обычный рабочий день, ничего особенного.
Output: {"sentiment":"neutral","score":5,"summary":"Нейтральное замечание без ярко выраженной эмоции."}
```

## Признаки хорошего и плохого промпта

| Критерий | Плохой промпт | Хороший промпт |
|---|---|---|
| **Конкретность** | «Напиши код» | «Напиши JavaScript-функцию, которая принимает массив объектов пользователей и возвращает только пользователей старше 18 лет, отсортированных по имени» |
| **Контекст** | «Исправь ошибки» | «Ты — senior Python-разработчик. Найди ошибки в этом Flask-роуте, укажи строку и предложи исправление» |
| **Формат** | «Проанализируй отзывы» | «Проанализируй отзывы и верни JSON: { sentiment, score, summary }» |
| **Ограничения** | «Объясни JWT» | «Объясни JWT за 100 слов для разработчика с базовым знанием JavaScript, без жаргона» |
| **Ёмкость** | «Будь так любезна, дорогая нейросеть, подскажи-расскажи мне пару идеек...» | «Представьте перечень химических элементов ядра Солнца» |

**Ключевой признак плохого промпта** — модель не может однозначно определить, что от неё требуется, и выбирает наиболее вероятный ответ из обучающих данных. **Признак хорошего** — результат можно использовать без дополнительной интерпретации и он воспроизводим при повторных вызовах.

## Статьи и ресурсы для изучения

1. **The Prompt Report: A Systematic Survey of Prompt Engineering Techniques** (arXiv, 2025) — наиболее полный академический обзор: 33 термина, таксономия техник, best practices для SOTA-моделей.

2. **Prompt Engineering | web.dev** — практическое руководство от Google, разбирает компоненты промпта (context, instruction, input variables, output format, examples, constraints) на примере реального приложения.

3. **Prompt Engineering: Part 1 — Introduction to Effective Communication with LLMs** (Siemens Blog) — статья, ориентированная на разработчиков, с акцентом на интеграцию промптов в приложения и агентные системы.

4. **Prompt engineering techniques** (Microsoft Learn) — базовые концепции и паттерны, применимые к GPT-моделям; полезно для тех, кто работает с Azure OpenAI.

5. **AI-Fundamentals-for-Developers / Prompt Engineering** (GitHub) — компактный репозиторий с «золотыми правилами» промптинга, шкалой качества промптов и примерами для типовых разработческих задач.

6. **Prompting Guide** (promptingguide.ai) — открытый ресурс с постоянно обновляемой коллекцией техник, статей и ноутбуков, включая few-shot, chain-of-thought и другие паттерны.

7. **Формулирование задачи для нейросети** (Яндекс Образование) — русскоязычный хендбук с принципами ясности, ёмкости, логичности и наглядности, а также примерами плохих и хороших формулировок.

Для быстрого старта рекомендую начать с материалов web.dev и репозитория AI-Fundamentals-for-Developers — они дают минимально достаточный набор концепций без академической перегрузки, а уже затем переходить к The Prompt Report для системного понимания таксономии техник.
