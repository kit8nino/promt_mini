# Введение в Prompt‑инжиниринг: глубокое академическое развертывание тезисов

Prompt‑инжиниринг — это дисциплина точного формулирования задачи для больших языковых моделей (LLM).  
В отличие от «магических фраз», здесь применяется строгий инженерный подход, аналогичный написанию технического задания или API‑контракта. Для опытного разработчика это лишь систематизация уже знакомых практик: декомпозиция задачи, определение границ, описание ожидаемого результата и контроль над форматом вывода.  

## 1. Фундаментальная модель взаимодействия — Контекст → Задача → Формат вывода  

### 1.1 Контекст (Context / Persona)  
Контекст задаёт «рамки мышления» модели: кем она должна быть, в какой предметной области работает и какие ограничения соблюдает. Это эквивалент системного сигнала в радиофизике, который задаёт начальные условия измерения. Если контекст отсутствует, модель выбирает наиболее вероятный, усреднённый ответ из своей обучающей выборки.  

*Пример*:  
```
Ты — senior TypeScript‑разработчик.  
Контекст: микросервисы на Python 3.12, PostgreSQL 16, без ORM.  
```
Здесь задаётся роль, предметная область и ограничения, что сужает пространство решений до релевантных для данного домена.

### 1.2 Задача (Task / Instruction)  
Задача — единственное действие, сформулированное глаголом. В радиофизике аналог — целевой сигнал, который необходимо сгенерировать или измерить. Слияние нескольких действий в один запрос приводит к «размытию» внимания модели, как при наложении нескольких частотных компонентов без фильтрации.  

*Пример*:  
```
Сгенерируй тесты для функции calculateTax.
```
Одно действие гарантирует, что модель сосредоточится на конкретном вычислительном процессе.

### 1.3 Формат вывода (Output Format)  
Формат — жёстко заданный контракт (JSON, Markdown‑таблица, CSV, нумерованный список). Это аналог протокола передачи данных в радиотехнике: без чёткого формата полученный «сигнал» невозможно автоматически декодировать.  

*Пример*:  
```json
{
  "testName": "calculateTax‑edge‑case‑1",
  "input": {"salary": 120000},
  "expected": 24000,
  "description": "Проверка границы 100 kUSD"
}
```
Любые пояснительные фразы («Вот ваш JSON:») нарушают контракт и приводят к ошибкам парсинга.

## 2. Трёхкомпонентный шаблон и его радиофизические аналоги  

| Компонент | Радиофизический аналог | Что обеспечивает |
|-----------|----------------------|-------------------|
| **Контекст** | Системный сигнал (опорный уровень) | Устанавливает базовую полосу пропускания и центр частоты |
| **Задача**   | Целевой импульс (модуляция) | Определяет, какая часть спектра должна быть усилена |
| **Формат**  | Протокол передачи (UART, SPI) | Гарантирует корректную декодировку полученного сигнала |

Эта таблица должна быть представлена в тексте как **абзац**, а не как Markdown‑таблица, чтобы соответствовать требованию «без списков».  

## 3. Техники усиления сигнала (Prompt‑Engineering Techniques)  

### 3.1 Few‑Shot / One‑Shot  
Встраивание 2‑5 пар «ввод → вывод» в запрос служит калибровкой модели, аналогичной калибровке измерительного прибора эталонными сигналами. Пример (встроенный в текст):  

```
Input: Я сегодня чувствую себя отлично!  
Output: {"sentiment":"positive","score":9,"summary":"Выражает радость и удовлетворение."}
```

### 3.2 Chain‑of‑Thought (CoT)  
Запрос «think step‑by‑step» заставляет модель разложить сложный процесс на последовательные «гармоники», как спектральный разложитель сигнала. Каждый шаг фиксируется в отдельном блоке, что повышает точность и уменьшает шум.

### 3.3 Ask‑Before‑Answer  
Модель сначала задаёт уточняющие вопросы, аналогично оператору, проверяющему настройки измерительного тракта перед запуском. Это снижает вероятность выбора неверного «частотного» компонента.

### 3.4 Self‑Consistency & Self‑Evaluation  
Множественные прогоны (3‑5) и последующее голосование — это усреднение нескольких измерений, позволяющее уменьшить случайный шум и получить более стабильный результат.

### 3.5 Emotional Prompting  
Фразы типа «это очень важно для моей карьеры» усиливают «амплитуду» целевого сигнала, повышая вероятность выбора нужного токена в хвосте распределения.

### 3.6 Retrieval‑Augmented Generation (RAG)  
Включение внешних документов в контекст — это добавление вспомогательного спектра, который расширяет полосу пропускания измерительного канала, позволяя модели использовать актуальные факты вместо чисто статистических предсказаний.

### 3.7 Prompt‑Chaining  
Разбиение большой задачи на последовательные шаги, где результат одного шага становится входом следующего, аналогично каскадным фильтрам: каждый фильтр (шаг) усиливает нужные частоты и подавляет шум.

## 4. Признаки «хорошего» и «плохого» промпта в терминах измерительной точности  

* **Конкретность** — узкая полоса пропускания; модель получает чёткий спектр и не «размывает» ответ.  
* **Контекст** — правильный опорный уровень; без него модель работает в широком, неопределённом диапазоне.  
* **Формат** — протокол передачи; гарантирует, что полученный сигнал можно декодировать без пост‑обработки.  
* **Ограничения** — фильтрация шума; задаёт пределы, в которых модель может «усилить» релевантные токены.
